# Plan — motion belongs to the family (2026-10-17)

Read `CLAUDE.md`, `CONTEXT.md`, `docs/families.md` and ADR 0010 first.
Status: **proposal, not started.** Tick the checkboxes as you go.

## 1. The problem

A family decides how everything *looks*, but not how four components *move*.
Their enter/leave animations are written in JavaScript, inside the Svelte
wrapper, with Svelte's built-in transitions:

| Component | File | Today |
|---|---|---|
| Dialog   | `src/lib/components/Dialog.svelte`   | `transition:scale={{ start: 0.95, duration: 150 }}` on `.dialog-box` |
| Dropdown | `src/lib/components/Dropdown.svelte` | `transition:fly={{ y: ±4, duration: 120 }}` on the panel |
| Toast    | `src/lib/components/Toast.svelte`    | `in:fly={{ y: ±16, duration: 180 }}`, `out:fly={{ x: 24, duration: 160 }}`, `animate:flip={{ duration: 180 }}` |
| Alert    | `src/lib/components/Alert.svelte`    | `out:slide={{ duration: 160 }}` |

The numbers and the shape of the movement are frozen in the component. Peony
cannot make its dialog bloom softly while sunflower snaps it in; no theme
parameter can slow it down; and the bundle a user downloads carries a motion
it has no CSS for.

Everything else that moves is already CSS and already the family's: the menu
fold (`grid-template-rows`), the sidebar rail (`width`), the toggle knob
(`grid-template-columns`), the switch indicator (`left`/`width`).

## 2. Why Svelte is needed at all

CSS alone can animate an element **entering** (`@starting-style`) and
**leaving** (`transition-behavior: allow-discrete` on `display`/`overlay`).
Both are below the project's 90% support floor (≈88% in 2026-10), so they are
ruled out for now (CLAUDE.md: 90% browser support minimum).

What is missing without them is one thing only: **keeping a removed element in
the DOM long enough for its leave animation to play.** Svelte's transition
mechanism does exactly that. So Svelte keeps the *timing of removal*; the
*animation itself* moves to the CSS.

## 3. The idea in one sentence

The component marks the phase (`data-motion="enter"` / `"leave"`) on the
element; the family's CSS animates that phase; a small reusable Svelte
transition, `motion`, reads from the computed style how long the family's
animation lasts and holds the element that long.

```
Svelte wrapper              motion (src/lib/motion.ts)          family CSS (look)
──────────────              ──────────────────────────          ─────────────────
{#if shown}                 sets data-motion="enter"     ──▶    [data-motion=enter] { animation: … }
  <div transition:motion>   reads animation-duration
                            returns { duration }
{/if}  ── shown=false ──▶   sets data-motion="leave"     ──▶    [data-motion=leave] { animation: … forwards }
                            reads animation-duration
                            Svelte removes the node after it
```

No animation declared by the family ⇒ duration 0 ⇒ the element appears and
disappears instantly. That is the correct default, not a bug.

## 4. Example — the Dialog

### 4.1 Wrapper, before

```svelte
import { scale } from 'svelte/transition';
let duration = $derived(animated ? 150 : 0);
…
<div class="dialog-box"
     transition:scale={{ start: 0.95, duration: reduced() ? 0 : duration }}
     onoutroend={finish}>
```

### 4.2 Wrapper, after

```svelte
import { motion } from '$lib/motion.js';
…
<div class="dialog-box"
     transition:motion={{ enabled: animated }}
     onoutroend={finish}>
```

`reduced()` and the `150` disappear from the component: reduced motion is a
media query in the CSS (§6.4), the duration is the family's.

### 4.3 Family CSS — peony (`src/scss/families/peony/dialog.scss`, `look`)

A soft bloom: slightly from below, scaled up past 1 then settling.

```scss
.dialog {
	--dialog-enter: 0.32s cubic-bezier(0.22, 1, 0.36, 1);
	--dialog-leave: 0.18s cubic-bezier(0.4, 0, 1, 1);
}
.dialog-box[data-motion='enter'] {
	animation: dialog-peony-in var(--dialog-enter);
}
.dialog-box[data-motion='leave'] {
	animation: dialog-peony-out var(--dialog-leave) forwards;
}
@keyframes dialog-peony-in {
	from { opacity: 0; translate: 0 0.75em; scale: 0.96; }
	60%  { opacity: 1; scale: 1.01; }
	to   { translate: 0 0; scale: 1; }
}
@keyframes dialog-peony-out {
	to { opacity: 0; translate: 0 0.4em; scale: 0.98; }
}
@media (prefers-reduced-motion: reduce) {
	.dialog-box[data-motion] { animation: none; }
}
```

### 4.4 Family CSS — sunflower (neobrutalism), same component

Hard, short, no easing past the point: a stamp.

```scss
.dialog-box[data-motion='enter'] { animation: dialog-sunflower-in 0.12s steps(3, end); }
.dialog-box[data-motion='leave'] { animation: dialog-sunflower-out 0.08s linear forwards; }
@keyframes dialog-sunflower-in  { from { translate: 0.4em 0.4em; box-shadow: none; } }
@keyframes dialog-sunflower-out { to   { opacity: 0; } }
```

Same Svelte wrapper, same markup, two different motions, and the bundle the
user downloads contains the motion it shows.

## 5. The `motion` transition — exact behaviour

File: `src/lib/motion.ts` (hand-written source; not generated).

```ts
import type { TransitionConfig } from 'svelte/transition';

export interface MotionParams {
	/** false: no phase is marked, duration 0 — the `animated` prop of a wrapper. */
	enabled?: boolean;
	/** Override the phase names, e.g. Toast's 'enter' | 'leave-swipe'. */
	enter?: string;
	leave?: string;
}

export function motion(
	node: Element,
	{ enabled = true, enter = 'enter', leave = 'leave' }: MotionParams = {},
	{ direction }: { direction: 'in' | 'out' | 'both' }
): TransitionConfig {
	if (!enabled) return { duration: 0 };
	const phase = direction === 'out' ? leave : enter;
	node.setAttribute('data-motion', phase);
	const duration = longestAnimation(node);
	if (direction !== 'out') {
		// Clear the mark once played, so the element rests in its normal
		// state and a later leave starts from it.
		setTimeout(() => {
			if (node.getAttribute('data-motion') === phase) node.removeAttribute('data-motion');
		}, duration);
	}
	return { duration };
}

/** ms of the longest animation on the node: max over the comma-separated
 *  lists of (delay + duration × iteration-count). 'infinite' counts as 0. */
export function longestAnimation(node: Element): number { … }
```

Rules the implementation must respect:

1. **Read after marking.** `setAttribute` first, then `getComputedStyle` — the
   read forces a style recalc, so the family's `[data-motion=…]` rule is in it.
2. **Durations are lists.** `animation-duration: 0.3s, 0.1s` with
   `animation-delay: 0s, 0.25s` → 350 ms. Parse `s` and `ms`. Iteration count
   `infinite` → ignore that entry (a spinner inside must not hold the node
   forever).
3. **No CSS transition sneaks in.** Only `animation-*` is read. Families animate
   phases with `@keyframes`, never with `transition` (a transition needs a
   before-state the browser may not have rendered).
4. **Leave keeps its last frame.** The family writes `forwards` on the leave
   animation, otherwise the element flashes back to full opacity in the frame
   before Svelte removes it. Document this in the contract (§6).
5. **`direction: 'both'`** (from `transition:`) — Svelte calls the function
   once per direction with `'in'` or `'out'` in Svelte 5; treat anything but
   `'out'` as enter.
6. **Interrupted transitions.** If a leave starts while the enter is playing
   (dialog closed immediately), setting `data-motion="leave"` replaces the
   running animation: the browser starts the leave from the current frame
   only if the keyframes have no `from`. Recommend leave keyframes with a `to`
   only (as in §4.3) — they then start from wherever the element is.
7. **SSR.** Transitions do not run on the server; nothing to guard.
8. **Reduced motion is CSS.** `motion` does not read `matchMedia`. If the
   family sets `animation: none` under `prefers-reduced-motion`, duration is 0.
   Remove each wrapper's own `reduced()` helper.

Return value: only `{ duration }`. No `css`, no `tick`: Svelte must not
generate its own keyframes, it only waits.

## 6. The contract for families

Add to `docs/families.md` a section **Motion**:

1. A component that moves declares its phases in its file header's plumbing
   contract, e.g. for `dialog.scss`:
   ```
   Motion (set by the wrapper, animated by the look):
	.dialog-box[data-motion="enter"|"leave"]
	--dialog-enter / --dialog-leave   duration + easing, family-chosen
   ```
2. The `structure` mixin writes nothing about motion. Motion is `look`.
3. Keyframe names are **`<namespace>-<family>-<phase>`** (`dialog-peony-in`).
   `@keyframes` names are global; two families can be on one page (the app's
   chrome is peony renamed to `ui-`, next to the previewed family), and a bare
   `dialog-in` from one would replace the other's.
4. Leave animations use `forwards` and only a `to` frame (§5 rules 4 and 6).
5. Every family writes a `prefers-reduced-motion: reduce` block that sets
   `animation: none` on its `[data-motion]` elements.
6. A family that wants no motion writes nothing: elements appear instantly.
7. Optional: expose speed as a parameter (e.g. peony `motion-speed`, a factor
   multiplied into the durations: `calc(0.32s * var(--motion-speed))`).
   Parameters belong to the family — do not add a shared one.

## 7. Phases per component

| Component | Element marked | Phases | Notes |
|---|---|---|---|
| Dialog   | `.dialog-box` | `enter`, `leave` | Keep `onoutroend={finish}`: it is what closes the `<dialog>` after the leave. The backdrop (`::backdrop`) can be animated by the family on `.dialog:has(> .dialog-box[data-motion=…])::backdrop`. |
| Dropdown | the panel (`.dropdown-content` or as named in the file) | `enter`, `leave` | Today `y` depends on `side` (top/bottom). The panel already carries the side in its class/attribute — the family writes two keyframes, or uses a custom property `--dropdown-from: -0.25em` set per side. |
| Toast    | each toast | `enter`, `leave` | Top vs bottom stack: same as Dropdown, from a side attribute. `animate:flip` stays in Svelte (it is layout — the other toasts closing the gap — not a look); its 180 ms may become a CSS custom property read the same way, optional. |
| Alert    | `.alert` | `leave` only | Today `slide` animates height to 0 so the content below closes the gap. With keyframes that is `grid-template-rows` or `height` on a wrapper; acceptable alternative: fade only, and the gap closes instantly. Decide with the user. |

## 8. Glossary and ADR

- `CONTEXT.md`: add **motion** — "the movement of a component entering or
  leaving the page. The wrapper marks the phase (`data-motion`), the family's
  look animates it." Add **phase** (`enter`, `leave`).
- `docs/adr/0011-motion-is-the-familys.md`: decision = §3; alternatives
  rejected:
  - *A prop on the component (`transition={fade}`)* — puts the choice in the
    page author's hands, per instance; a family can no longer give its look a
    movement, and the bundle's CSS does not describe it.
  - *Svelte transitions reading custom properties (`--dialog-duration`)* —
    only the numbers become the family's, not the shape; a family cannot say
    "bloom" or "stamp".
  - *Pure CSS (`@starting-style`, `allow-discrete`)* — the target, below 90%
    support today. When it passes, `motion` can be deleted and the families'
    CSS kept almost as is (`[data-motion=enter]` → `@starting-style`).

## 9. Data attribute, not a class

`data-motion` is an attribute on purpose: `gen-components` fails if a family
ships a class no component classifies, and a phase is not a variant, axis or
flag — it is a transient state set by script, like `aria-expanded`.

## 10. Chrome prefixing

`scripts/build-css.mjs` → `prefixChrome()` renames classes and custom
properties for the app's chrome (`.x` → `.ui-x`, `--x` → `--ui-x`). It must
also rename **`@keyframes` names and their uses** in `animation` /
`animation-name` (`dialog-peony-in` → `ui-dialog-peony-in`). Without it, the
chrome and a previewed peony share keyframe names (harmless while identical,
wrong as soon as a theme parameter changes nothing — keep them apart anyway).
