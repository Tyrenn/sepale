# 99 — Migration

What the 19 shipped themes lose, and what replaces it. A theme is a FILE —
`static/themes/*.css` — and `presets.ts` holds only names and URLs; a key no
control reads is dead weight that sits in the file and changes nothing.

**`gen:themes` must still pass**: every shipped theme survives being read back
and regenerated byte for byte, or the build fails. That check is the acceptance
test for this whole document.

## The form leaves no trace

Moving a control in Common and moving the same control inside a section produce
**the same kind of file** — the Common one writes N sections, the section one
writes one, and the file records only the result. So there is nothing about the
form to detect on reopen.

Which sections have left Common IS detectable, and it is detected rather than
stored: the biggest bucket of agreeing sections is Common's answer, and the
rest are overrides. **No sentinel is needed for that, and no `--common-*`
variable.** A theme written by hand opens with its overrides marked.

Sentinels are still needed for every control whose value is not recoverable
from the CSS — a group's type, chiefly. Keep the existing mechanism.

## The procedure, as it actually ran

`scripts/make-themes.mjs` re-derives all nineteen **through the schema**: it
picks the modes and moves the controls a person would have moved, and
`serialise()` writes the result. So a shipped theme is by construction a file
the form could have produced, and it round-trips.

It is a one-off, not a mechanism the repo keeps — but it is the thing to reach
for after any rename. Two bugs it carried, both of the silent kind:

- `--color-scheme` was caught by the `--color-*` harvester, turned into a
  `{source, shade}` pair and stringified over the correct entry:
  `[object Object]` in seven shipped files.
- it read only the colours, so the per-theme GEOMETRY was dropped — coffee's
  0.1rem fields, retro's radii, daisy's depth, half of cosmos's pen. A missing
  variable renders as neutral and no check could see it, which is why
  `check:defaults` now exists.

## Key by key

### Colours

Themes that set `--color-card/3/4`, `--color-on-background` or
`--color-border` explicitly **keep them, as Custom**. The derived defaults from
`01-colours.md` apply only where a theme was silent. Nothing is lost, and new
themes get the nine-colour shortcut.

`--color-on-<semantic>` keys are dropped: they were always derived and never
controls.

### Every colour becomes a pair

`<slot>-color` stays; `<slot>-shade` is new and defaults to `0`. A theme that
wrote a literal colour is a **Custom** box and needs no change beyond the new
key being absent (absence = `0`).

### Hover — the four modes collapse into one box

| Was | Becomes |
|---|---|
| `action-hover: darken` + `action-hover-amount: 7%` | Derived from **Own**, shade `0.07` |
| `action-hover: lighten` + `10%` | Derived from **Own**, shade `0.10` — the direction is now automatic, so darken and lighten are the same setting |
| `action-hover: tint` + `8%` | Derived from **Text**, shade `0.08` |
| `action-hover: none` | shade `0` |

Dropped: `action-hover-mix`, `action-hover-mix-color`,
`action-hover-border-mix`, `action-hover-border-mix-color`,
`action-press-mix`, `action-press-mix-color`, `action-press-border-mix`,
`action-press-border-mix-color`. The box writes them, and the press still
derives at `× 1.6`.

### Corners and the hand-drawn look

`action-corner`, `field-corner`, `selector-corner` disappear. The **radius**
moves to Common's Radius group; the **wobble** moves to Common's Hand-drawn
checkbox.

- daisy, dahlia, sunflower → Hand-drawn **off**.
- cosmos → Hand-drawn **on**, strength `1`, tilt `0.4deg`.

cosmos's four angle keys (`field-angle`, `selector-angle`, `container-angle`,
`marker-angle`) collapse into Hand-drawn's single **tilt**, spread by each
section's writer over whatever that section rotates.

### Radius — who detaches

| Theme | Radii | Mode |
|---|---|---|
| the 13 daisy themes | `0.25rem` controls / `0.5rem` boxes | 10 of 13 follow Common — that is the ×1 / ×2 factor |
| dahlia ×2 | `0.375` / `0.25` / `0.625` | Selectors and Container detach |
| cosmos ×2 | `0.75` / `0.5` | Container and Feedback detach |
| sunflower ×2 | — | check on migration |

Same for border width and shadow: dahlia is the sole dissenter in the measured
data (17/19 and 15/19), and it was already the theme that needed per-section
control.

### Motion

`--transition-duration` and `--transition-easing` are deleted, with their eight
per-section copies (`action-`, `field-`, `selector-`, `swatch-`, `tabs-`). Any
theme key naming them is dropped. One duration survives, in Action's *Press
animation*.

### The per-component second level

Dropped from every theme: the `radio-*`, `toggle-*`, `range-thumb-*`,
`swatch-*` and `tabs-*` keys that only restated their section's answer, and the
thirty-eight `menu-*` keys the Container *Item* group now covers. Where a theme
set a value **different** from its section level, either lift it to the section
level or drop it — and say which, per theme, in the commit message.

### Geometry

Already done in the tree: 35 lengths read `var(--<section>-scale)` and the
formulas stay in `_defaults.scss`. Nothing further.

## Procedure

1. Write the schema and one section. Run `check:theme`; it names every
   variable no control reaches. **Paste that list into `internal`.** Do not
   write it from memory.
2. Translate the presets for that section. Run `gen:themes`; it fails on any
   theme that does not round-trip.
3. **Render it.** `npm run dev`, walk the components in a light and a dark
   theme with hover / focus / disabled / checked. CSS that compiles is not CSS
   that looks right, and every wrong family this project shipped was written
   without looking at one.
4. Only then the next section.

## Scripting traps, paid for once already

- A search-and-replace on a bare control id also eats its mentions inside
  `vars:` arrays. Match the entry, not the string.
- Walking backwards from a match to find an entry's start stops at the entry's
  own `{` and leaves `{}` behind. Split the array into entries instead.
- A scanner that tracks string state must skip comments, or an apostrophe in
  `a row's own line` opens a string that never closes.
- Never mutate a string while iterating matches computed on the old string:
  the offsets drift and values get cut in half. Use a replace callback.
- A replacement anchored on `'# '` also hits `'## '` headings.
- Indentation-sensitive replacements match the wrong nesting level. A two-tab
  pattern will happily match four-tab lines and mangle an array.

Every one of these shipped a silent bug. Prefer writing the sections by hand
over scripting them; there are eight.
